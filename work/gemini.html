Overview

Gemini has the intelligence. The interface needs to catch up.

Google Gemini is one of the most capable AI assistants available, and its iOS app spends that capability carefully everywhere except the moment you open it. I rebuilt the app screen by screen, from signing in through to rating an answer, because redesigning something you have not drawn yourself is guesswork. Doing that is what showed me where the opening was thin, and the home screen is what I then redesigned.

The Problem

Three things I noticed while rebuilding it

The opening asks nothing and offers nothing

You are greeted by name and then handed the same suggestions as everyone else. The app already knows the time, the place and what you were last doing, and uses none of it.

An answer ends in a blank field

The moment a long answer finishes is the moment you are most likely to have a follow-up, and it is exactly when the interface stops helping.

Telling it something is wrong is a detour

Rating an answer badly should take a few seconds and return you to where you were, not send you somewhere you have to find your way back from.

The Redesign

The opening screen should already know something about you

I rebuilt the app screen by screen first, so that anything I changed would be measured against the real thing rather than against a memory of it. The home screen is where I then made the case for something different: the greeting stays, and the two suggestion columns beneath it do the work.

Final Screens

These run in the order a session actually happens, from signing in to giving feedback on an answer. It is one continuous thread: a beginner asking about Python, then asking for something longer, then telling the assistant the answer was not formatted well.

Signing in

The first screen does one thing. The account is already known, so the only decision left is whether to continue as yourself.

Home, with the suggestions in context

The redesigned opening, and the three frames show it cycling. Two labelled columns sit under the greeting: one reads the time and the place, offering late-night coffee in Oakland and then dinner near campus, while the other picks up the work already in progress, moving from the Python chat to a study app project with open questions. Because the cards rotate, the screen has something different to say each time it opens rather than repeating one generic set.

Drawer and search

Navigation stays at four items with recent chats listed beneath them, and the account sits at the bottom where it is out of the way. Search is the same list narrowed, with the keyboard already up.

A short answer

The first exchange. A beginner asks what a Python if statement does and gets two sentences and an everyday analogy back, with the response actions sitting directly beneath the text rather than behind a menu.

Composing a long prompt

The field grows with the prompt instead of scrolling inside three lines, so a long instruction can be read back in full before it is sent, and the send button stays where it was.

Structure in a long answer

Headings, bold labels and an inline code chip break a long answer into parts that can be scanned rather than read start to finish. The prompt above it collapses to three lines with a chevron to reopen it, and a floating control drops back to the newest text.

Code, and where to go next

After the code block the assistant asks where to take the learning next and offers two specific moves, both about the script just written. That is the difference between a thread continuing and a reader having to invent the next question in front of an empty field.

Feedback in three taps

Thumbs down opens the sheet straight away, with the common reasons as chips and a field for anything they do not cover, here a note about formatting. Submitting returns to the chat with the rating still showing and a toast at the bottom, rather than a modal that has to be dismissed.

Reflections

This project pushed me to think about AI interfaces differently, not just as chat windows, but as adaptive surfaces that should respond to who you are and what you're doing.

The feedback redesign was the most constrained problem: how do you make reporting feel frictionless without making the UI feel paranoid or over-engineered? The answer was reducing steps, not adding options.

If I continued this project, I'd explore how Gemini's home screen could learn across sessions, surfacing the right context before the user even has to ask.
